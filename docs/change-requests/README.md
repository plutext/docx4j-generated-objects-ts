# Change requests

Numbered proposals for changes to the hand-written part of this package (the facade in `src/`,
the package layout, the tests). Changes to the generated `modules/` are proposed in the compiler
repository (`plutext/jsonix-schema-compiler`, `docs/change-requests/`), changes to the runtime in
`plutext/jsonix`.

| CR | Title | Status |
|---|---|---|
| [CR-001](CR-001-namespace-prefixes.md) | The facade ships docx4j's namespace prefix table as the context default (`NAMESPACE_PREFIXES`; unused root declarations stripped until the runtime declares on demand) | Implemented 2026-09-10 |
| [CR-002](CR-002-wml-builders.md) | `builders/wml`: `wml` XML fragments with the standard declarations (wrapped in the container docx4j would put it in, since the runtime unmarshals global elements only; content controls by their first decisive descendant), text sugar `p` / `r` / `t` / `tbl` / `textOf` over `el`, and `walk` / `find` / `linkParents` | Implemented 2026-09-10 |
| [CR-003](CR-003-content-builders-from-core-ts.md) | `builders/wml` additions requested by core-ts's content API: `sdt` / `sdtPr` / `sdtProperty` / `sdtKindOf`, `inlinePicture`, `tr` / `tc`, `runItemsOf`, `rPrToElements` / `rPrFromElements`, `walkAll`, `toSource` / `isSugarExpressible` (phase B); `deepCopyAs` in the facade | Proposed 2026-09-16 |
| [CR-004](CR-004-round-trip-fidelity.md) | A round-trip fidelity test over parts Office wrote: unmarshal and marshal each through the facade and compare canonically, the kind of test that would have caught the losses docx4j's CR-021 to CR-023 closed (a trial run found a silent, total loss of a drawing part) | Phases A and B implemented 2026-09-23 and 2026-09-25 |
| [CR-005](CR-005-module-registry.md) | A bundler-friendly way to load the mapping modules: `src/modules.mts`, a registry of literal imports instead of one computed `import()`, with `MODULE_NAMES` derived from it, a `modules` option on `getContext` and `modulesFor` for a root's closure | Implemented 2026-09-24 |
| [CR-006](CR-006-ignorable-prefix-aliases.md) | An `mc:Ignorable` prefix the preferred-prefix table cannot produce, because the namespace is written as the default (`IGNORABLE_PREFIX_ALIASES`): Excel's `x` on slicer caches was dropped instead of declared, as docx4j's CR-024 declares it | Implemented 2026-09-24 |
| [CR-007](CR-007-per-call-runtime-options.md) | Per-call runtime options on the facade's four entry points (`@docx4j/jsonix` 3.4.0's `createUnmarshaller`/`createMarshaller` options): what unmarshalling dropped, what marshalling wrote, a prefix table for one call - which also retires the hand-rolled context derivation, and gives the fidelity test a direct report of losses in place of inference | Implemented 2026-09-27 |
| [CR-008](CR-008-ignorable-for-extension-namespaces.md) | A marshalled part declares the Office extension namespaces it uses as ignorable (`IGNORABLE_EXTENSION_NAMESPACES`, the twenty Office itself lists): `w16du:dateUtc`, or a caller's `w15` content, was written with no `mc:Ignorable` at all, which ECMA-376 Part 3 makes an error for a reader that does not understand it, and which Word 2010 refuses for an element (core-ts Word check 36) | Implemented 2026-10-04 |
| [CR-009](CR-009-type-kept-mc-branches.md) | Type what a kept `mc:AlternateContent` branch holds: the context declares globally the 61 WordprocessingML elements docx4j declares as roots and this mapping only within parents (`w:drawing`, `w:pict`, `w:tbl`, `w:t`, ...), so the lax wildcard types them as docx4j's does; and `v:shapetype` keeps `w14:anchorId`, which typing exposes as a loss. Requested by core-ts CR-010 phase 2 | Implemented 2026-10-18, released in 0.4.0 |
| [CR-010](CR-010-type-kept-pml-and-xdr-shapes.md) | Type the shapes a kept `mc:AlternateContent` holds in slides and spreadsheet drawings: `p:sp` and `p:cmAuthor`, the PresentationML roots docx4j declares and this mapping doesn't (ready, measured whole); the other `p:` and `xdr:` shapes (whole, but beyond docx4j: recommended through a docx4j CR first); the `xdr:` anchors (gated on `a14:legacySpreadsheetColorIndex`, which typing a kept checkbox anchor loses). Raised by core-ts CR-010 section 14.7 | Proposed 2026-10-18 |
| [CR-011](CR-011-declare-source-only-prefixes.md) | Declare from the source the prefixes only the source bound: a `Requires` or `mc:Ignorable` prefix `NAMESPACE_PREFIXES` and the aliases cannot produce (a private `zz9`; `shape2010`, a second prefix for `wps`) lost its declaration on marshal, since the typed tree keeps none, so a kept Choice named a prefix nothing declared. The facade records the source's bindings at unmarshal, finds them by `PARENT` at marshal, and declares from them before the table. Requested by core-ts (its CR-010 section 14.9), found by the editor | Proposed 2026-10-20 |
